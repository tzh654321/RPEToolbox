## 回收站上万张 ico 的根因与修复

- 现象：用户回收站出现上万张项目 ico，删除时间=上次运行时间。
- 根因（实测数据）：`_keep_taskbar_icon` 每 3 秒检查一次类图标，Tk 会不断把类图标重置回去，
  于是 `_apply_taskbar_icon` 被反复调用——**构造阶段 29 次、之后约 3.1 次/秒**；
  旧实现每次都 `NamedTemporaryFile` 生成 2 个 .ico 再 `os.remove`，即 **约 22,000 个/小时**。
  在本环境 `os.remove` 被 safe-delete 钩子接管 → 删除动作进回收站，于是回收站被 .ico 淹没。
- 修复（app.py）：`_icon_temp_files()`（ICO 只转换一次并缓存路径，前缀 `rpet_icon_`）、
  `_ensure_icons()`（LoadImageW 句柄缓存）、`_release_icons()`（退出时 DestroyIcon + 删文件，
  `shutdown()` 调用并注册 `atexit` 兜底）。新增 `tests/_test_icons.py`（7 项）锁住。
- 验证：同样 29 次调用 → 临时 .ico 从 58 个降到 2 个；运行 7 秒不增长；退出后归零。
- 遗留：当天更早的运行在 %TEMP% 留下 18 个 `rpet_icon_*.ico`（约 0.4MB），没删（本环境删除会再进回收站）。

## 修复「模组 image_to_notes 的选项界面创建失败」启动弹窗（并连带修掉 3 个真 bug）

**用户报的 bug**
- 现象：每次打开都弹「模组 image_to_notes 的选项界面创建失败，功能仍可使用。」
- 根因：`build_options` 里 `command=app.select_image_file`，但 `select_image_file` 只是该模组文件里的
  模块级函数 `def select_image_file(app)`——app 上没有这个属性 → `AttributeError`。
  同批自动切分脚本把旧的 `self.select_image_file` 机械改写成 `app.select_image_file` 留下的；
  正确写法是 `command=lambda: select_image_file(app)`（同批 `score_cut_merge`/`vertical_pitch` 就是这么写的）。
- 同类缺口精确扫描：只发现 2 处（`select_image_file`、`select_midi_file`），两处都已改。
  扫描方法值得复用：把「模组内 `def X(app` 的函数名」∩「该文件里出现的 `app.X`」- RPEToolbox 已有属性 = 缺口。

**连带修掉的真 bug（都不在原报障范围内，但都会让功能失效）**
1. `i18n.t()` 的 `NameError`：上次给首参改名 `key`→`text_key` 时漏改两处 `return key`，
   任何一次「取不到文案」都会抛 NameError 而不是优雅回退。
2. **语言切换等于失效**：`load()` 无参会按「环境变量 > 默认」取（无视已选语言），

   → 菜单切英文后下一次 `t()` 又把文案拉回中文。
   重构为 `_read(code)`（按语言代码缓存，只读）+ `load(code=None)`（只读）+ `set_language(code)`（唯一改状态的入口）。
3. **点标签页后状态条与「转换」失效**：`_on_tab_changed` 把 `current_function` 设成**不带序号**的
   `item["name"]`，而 `self.functions` 的键是「序号. 名称」→ 解析不到功能。
   修法：写回 `self.function_names[index]`；另加 `_resolve_function(label)` 兼容
   「序号. 名称 / 纯名称 / 模组 key」三种写法，`on_function_change`/`_update_status_text`/`process_data` 统一走它。
4. 语言文件缺 `vertical_pitch` / `score_cut_merge` 两条 `functions[]` 条目 → 新功能标签显示原始 key。

**可诊断性**

**5. 纵连音高（基本重写）**

## 第三轮：菜单改名 / 纵连音高细节（用户 10 项反馈）

1. **功能/禁用 → 功能/启用**：`menu.disable` 改 `menu.enable`（zh「启用」/ en「Enable」），
   代码里 `disable_menu` 属性一并改名 `enable_menu`，这样"勾 = 启用"的语义才自洽。
2. **滑音实际还是非滑音**：`process()` 原来完全没读 `state["glide"]`。
   新增 `_glide_boundaries()`：重复频率随时间线性变化时，总数 = `时长 × (f1+f2)/2`，
   第 k 个音符的时间由 `∫₀ᵗ f(τ)dτ = k`（f 线性）反解 `a·t² + b·t - k = 0`。
   实测 C4→C6 持续 2 秒：1308 个音符，首步长 0.0076s → 尾步长 0.0019s（越来越密 = 音高上升）。
3. **长条首尾相接**：原来 `first` 保持原 `endTime`（整段），后面却从 `span/count` 开始 → 第一个长条盖住了全部。
   现在 hold 的所有分段都由 `marks` 生成，`第 i 个 endTime = 第 i+1 个 startTime`（实测最大缝 0）。
   **踩坑**：`marks` 一开始按「拍」算却又乘了一次 `bpm/60` → 时长被放大 2 倍（1.0→3.0 变成 1.0→5.0）。
   统一成「marks 用拍」后修正；单位混用建议在函数名里写清楚（`_seconds` / `_span_beats`）。
4. **预览窗口方向**：改成**下方较早、上方较晚**（原来上早下晚）。
5. **时间单位为拍**：网格刻度直接标拍数（0/0.5/1/…），不再换算成秒、也不带 `s`。
6. **输入/输出框等高**：原来两个 Frame 都用 `pack(expand=True)`，实际差出一大截（纵连音高页 396 vs 107）。

## 第五轮：预览速度/时长/进度线 + 非法 endTime（用户 4 项反馈）

### 13.1 打包版 exe 无法启动（Security validation failure）

**现象**：启动打包 exe 弹出 "Security validation failure: failed to obtain executable path for parent proces!"
然后退出。
**根因**：PyInstaller 6.22.1+ 的 onefile 父进程安全校验（GHSA-9fxf-4qw3-ghmr，#9492）：子进程会解析
父进程的可执行文件路径并比对。而 `launcher.relaunch_as_pythonw` 在冻结环境下
把 `sys.executable`（就是 exe 自己）当成 pythonw 又重启了一遍，且新进程继承了
`_MEIPASS2` 环境变量 → 被当成子进程去校验父进程，而启动它的应用实例随即 SystemExit 退出，
父进程路径无法解析 → 报错。
**修法**：`relaunch_as_pythonw` 开头加 `if getattr(sys, "frozen", False): return`（--windowed 的 exe
没有控制台，重启自身本就没意义）。

### 13.2 模组与语言文件铺到 exe 同级

- `resources._project_root()`：冻结时若 **exe 同级有 assets/** 则优先用外部的（改语言/功能介绍不用重打包）；
- `mods_loader.mods_root()`：冻结时若 **exe 同级有 rpe_toolbox/mods/** 则优先用（加模组不用重打包）；
  因为 _MEIPASS 里只有编译产物，没有 mods 的 .py 源文件，原来的目录扫描在冻结后会扫到空。
- `build_exe.py` 新增 `deploy_external_files()`：打包后自动把 assets 与 rpe_toolbox/mods 铺到 exe 同级（覆盖式拷贝，
  **不用 rmtree**——沙箱/钩子会拦截删除）。

### 13.3 打包环境的两个坑

- WorkBuddy 注入的 `sitecustomize`（PYTHONPATH 指向 shim）把 `os.remove` 重定向到回收站，
  PyInstaller `--clean` 删缓存时直接挂掉。解法：构建子进程清掉 PYTHONPATH，
  且 **不用 --clean**（直接删缓存目录也行）；铺文件用 `copytree(dirs_exist_ok=True)` 覆盖式拷贝。
- **从沙箱里启动打包 exe 会触发同样的 Security validation 弹窗**（沙箱限制了父进程路径查询），
  验证 exe 要用非沙箱方式启动；用户正常双击不受影响。

验证：重打包后启动 exe 截图 —— 外部 mods 加载出 7 个标签（用户配置禁用了 2 个）、
状态条显示新文案、暗色按钮换色生效。全量回归 **437 项断言全绿**。

### 13.4 exe 少了两个功能：rpe_toolbox.shared 没被收集

**现象**：exe 只有 7 个标签，缺 非线性切割 + 极坐标转换——恰好是依赖
`from rpe_toolbox.shared import ...` 的两个模组。模组是运行时 spec_from_file_location
动态加载的，PyInstaller 静态分析看不到它们的依赖，而主包里又没有任何静态 import
`rpe_toolbox.shared`（core.py 只在 docstring 里提到）→ shared 没被打进包体，
动态 import 失败 → LOAD_ERRORS 静默跳过。实测 `_MEIPASS/rpe_toolbox` 目录为空。
**修法**：打包加 `--collect-submodules rpe_toolbox`（整包收集，以后新模组的
主包依赖也不会再漏）。重打包后 9 个标签齐全（截图验证）。

## 第十二轮：关于弹窗显示字面量 {version}（用户 1 项）

`show_about` 调 `t("dialogs.about_text")` 时没传 `version`——i18n 的 `t()`
只在传了 kwargs 时才 format，于是界面直接显示字面量 "{version}"。
修法：app.py 顶部 `from . import __version__ as APP_VERSION`（定义在
`rpe_toolbox/__init__.py`，当前 "2026.7.12"），
`show_about` 改为 `t("dialogs.about_text", version=APP_VERSION)`。
教训：**文案模板里的占位符，调用时必须逐个传参**，
添新占位符后要搜一遍调用点（或让测试断言"填充后无残留 {xxx}"）。

**测试**：`_test_req17.py` **137 项**（K 段新增：show_about 弹窗内容含真实版本号且无 {version} 字面量；
中英文案填充后无残留占位符）。全量 **437 项断言全绿**。
